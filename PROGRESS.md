## 2026-10-12 — Three reported problems: reasoning default, native image vision, sub-agents always inherit the model
- **Problem 1 — nothing ever asked the model to think.** `provider.reasoning` shipped as `null` and no UI existed for it, so every reply ran on the model's own cheapest thinking budget. The plumbing already worked; only the value and the control were missing — and "never set" is invisible, which is why it survived. Now `DEFAULT_REASONING_EFFORT = "high"` in `src/core/reasoning-effort.js` plus `config/default.json`, and a Reasoning-effort row in **both** Settings UIs (`web-next/js/ui/settings.js`, `public/neo.js`).
  - **A naive default would have caused an outage, so it isn't enough on its own.** Setting an effort puts a `reasoning`/`reasoning_effort` key on every request; any endpoint that rejects unknown params would then 400 on **every message**. That trades a quiet quality problem for a total failure. So: `isUnsupportedReasoningError()` detects a genuine unknown-param 400, the provider retries once stripped, and **remembers** it per-instance — the user pays one failed round once, not forever. The detector is deliberately narrow (an auth/quota failure must not be mistaken for it and silently retried).
  - **The two wire dialects are not interchangeable** and were previously a pass-through: OpenRouter wants `reasoning:{effort}`, OpenAI wants `reasoning_effort:"high"`. Now chosen from the endpoint. An **object** config value still means that exact shape, so a working gateway profile is never silently rewritten into a 400ing one.
  - `updateRuntimeSettings` allowlists keys, so the Settings row would have **reported success while saving nothing** until `provider.reasoning` was added to it — and validated against the same level list the UI renders, so an arbitrary string from the browser can't reach a request body.
  - **A test caught a real bug here:** the fallback used `??`, and `null` is the *meaningful* "off" value — `x ?? y` treats null as absent, so "turn reasoning off" silently resolved back to high. Presence of the KEY is now what distinguishes unset from off.
- **Problem 2 — attached images went through a tool even when the model could see them.** `omni-loop.js` coerced every user turn to `content: String(message)`; the image crossed the wire only as a path in a text note, so the model reached for `describe_image`, which had no configured vision backend → `Failed/blocked: describe_image`, three times over. Now: a **vision-capable model gets the real pixels** as a native `image_url` content part and the tool is never called; **only a blind model** keeps the text note and the tool. Routing an image a model can already see through `describe_image` would send it to a *different* vision model and return a lossy text description of something the reader could see directly.
  - Attachments now travel **composer → sse.js → server → agent → loop**. The unit assertions call `buildUserMessage` directly, which proves the branch logic but not that a real turn reaches it — so the smoke also asserts all six wire hops, since "a helper that works and is never called" is exactly the bug being fixed.
  - The vision regex lived in **two files** and could disagree about whether a model has eyes. Now one `src/core/vision-capability.js`.
  - **Found and fixed a security gap while doing it:** `readableImageParts` refused traversal only because the target didn't exist — if it had been a real PNG outside the root, the bytes would have gone to the model. Explicit containment check added at the layer that actually reads from disk, plus `sanitizeAttachmentRefs` on the server (user-supplied paths naming files on disk are untrusted).
- **Problem 3 — sub-agents could run on a model the user never chose.** ~160 lines of ladder resolved an explicit per-call model, a configured default, a **dedicated provider profile**, and a rate-limit fallback — any of which could put a delegated review or patch on a different model than the one on screen, so quality was unpredictable and "which model ran this?" had no honest answer. Removed, not defaulted: the setting, the composer pill, its CSS, the classic-UI provider/fetch/test flow, `delegate_task {model,provider}`, the `switch_model "subagents"` scope, and `evaluate_work`'s reviewer-model swap. Sub-agents exist to add parallelism and context isolation, not to change who is thinking.
  - **Consequence, stated plainly:** a rate-limited sub-agent now **fails loudly** instead of quietly completing on a fallback model. That is the correct trade — a silently downgraded delegation produced a result the user would read as authoritative. The error says the fix is on the **main** binding, and no longer claims to have tried "every configured endpoint" when there is only one.
