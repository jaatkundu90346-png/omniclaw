## 2026-10-12 — Follow-up: effort pill in the composer, and two bugs that made Settings lie
- **"Reasoning option UI me hai hi nahi" — it was there, and it was lying.** Three separate causes, none of which was the missing feature:
  1. **It was buried.** The row rendered *after* the provider list and the whole connection form — several screens down. A control nobody can find is the same as a control that does not exist. Now it renders directly under the page intro, and there is a smoke asserting it renders **before** `paintList()` — anchoring on the loading spinner instead would have passed with the row back at the bottom.
  2. **It read the wrong object.** It read `health.provider`, whose payload is only `{id, ready, source}` — it has no `reasoning` field at all. So the row always showed the shipped default and silently ignored whatever the user picked. Now reads the saved config.
  3. **Nothing could save anyway — `POST /api/config` was blocked.** The route called `agent.tools.run("update_runtime_settings", body)` without `{operator:true}`. That is an OPERATOR tool: defined to be reachable from the UI/API and refused to the MODEL. The gate fired on this route too and returned **HTTP 200** `{blocked:true, code:"EOPERATOR"}`.
