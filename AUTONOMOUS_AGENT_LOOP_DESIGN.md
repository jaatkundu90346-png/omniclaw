# Autonomous Agent Loop Design for OmniClaw (Manus-Style)

## 1. Introduction

This document outlines the design for enhancing OmniClaw's agent loop to achieve a higher degree of autonomy, self-correction, and dynamic planning, mirroring the capabilities of a Manus-level AI agent. The current OmniClaw agent loop, while functional, primarily relies on heuristic planning and a single-pass tool execution model, with limited mechanisms for iterative refinement or robust error recovery. This redesign aims to introduce a more sophisticated "Think-Act-Observe-Reflect" (TAOR) loop, enabling the agent to continuously evaluate its actions, learn from outcomes, and adapt its strategy in real-time.

## 2. Current Limitations of OmniClaw's Agent Loop

Based on the analysis of `src/core/agent.js` and `src/core/planner.js`, the following limitations have been identified:

*   **Heuristic-driven Planning**: The `planner.js` primarily uses a set of predefined rules and intent detections to construct a plan (`buildPlan`). While `buildPlanWithModel` allows for model-driven planning, the overall structure is more reactive than proactive.
*   **Single-pass Tool Execution**: The `executeMessageRun` function in `agent.js` executes tools sequentially based on the initial plan. There's a `modelToolLoop` for iterative tool calls, but its depth and flexibility are limited (`maxRounds`, `maxToolCallsPerRound`).
*   **Limited Self-Correction**: Error handling is present, but it's mostly reactive (e.g., catching exceptions during tool execution). There isn't a structured mechanism for the agent to analyze *why* an action failed, reflect on its strategy, and devise an alternative approach.
*   **Absence of Explicit Reflection**: The agent does not explicitly reflect on its performance, the effectiveness of its plan, or the quality of its outputs. Learning from past interactions is primarily through memory storage (`memory.appendConversation`, `memory.addResearch`), but this doesn't directly feed back into the active decision-making loop for self-improvement.
*   **Static Context Management**: While context is assembled for the LLM call, the dynamic management and prioritization of context based on ongoing task needs could be improved.

## 3. Manus-Style Autonomous Agent Loop: Think-Act-Observe-Reflect (TAOR)

The proposed autonomous agent loop will follow a TAOR cycle, allowing for continuous reasoning and adaptation. Each cycle will involve:

### 3.1. Think: Dynamic Planning and Goal Decomposition

Instead of a single plan, the agent will maintain a dynamic task queue and a hierarchical plan. The 
agent will maintain a dynamic task queue and a hierarchical plan.

**Key components:**

*   **Goal Manager**: Responsible for breaking down high-level user requests into smaller, actionable sub-goals. It will maintain a goal stack or tree, allowing for recursive decomposition.
*   **Dynamic Planner**: Generates a sequence of actions (tool calls, internal reasoning steps, sub-delegations) to achieve the current sub-goal. This planner will be more sophisticated than the current heuristic planner, leveraging the LLM for complex reasoning and considering the agent's current state, available tools, and past experiences (semantic memory).
*   **Contextual Reasoning Engine**: Assembles the most relevant context (from semantic memory, current session transcript, workspace files, etc.) for the LLM to make informed planning decisions. This will be more dynamic and adaptive than the current fixed context assembly.

**Process:**
1.  **Receive User Request**: The initial user message is processed by the Goal Manager to establish the top-level goal.
2.  **Decompose Goal**: The Goal Manager, potentially with LLM assistance, breaks down the goal into a set of initial sub-goals.
3.  **Plan for Sub-Goal**: The Dynamic Planner generates a plan (a sequence of steps) for the most urgent or highest-priority sub-goal. This plan can include:
    *   **Tool Calls**: Utilizing existing and newly added tools (semantic memory search, deep research, visual browser operations).
    *   **Internal Monologue/Reasoning**: Steps where the agent explicitly thinks, analyzes, and refines its understanding or strategy.
    *   **Sub-Delegations**: Assigning parts of the task to other specialized agents (if implemented).

### 3.2. Act: Execute Actions and Tools

This phase involves executing the steps generated by the Dynamic Planner. The existing `tool-registry.js` and `shellExecutor` will be leveraged, but with enhanced capabilities.

**Key components:**

*   **Enhanced Tool Execution**: The `executeMessageRun` will be modified to handle the new types of steps (e.g., internal reasoning, sub-delegations) and to provide richer feedback on tool execution outcomes.
*   **Multi-Provider Fallback Integration**: The `MultiProviderFallback` module will be deeply integrated to ensure robust and resilient execution of LLM-dependent steps, automatically switching providers if one fails.
*   **Asynchronous Execution & Monitoring**: Support for long-running tasks and parallel execution where appropriate, with continuous monitoring of their status.

**Process:**
1.  **Execute Step**: The agent executes the next step in the current plan.
2.  **Record Outcome**: The outcome of the action (success, failure, partial result, tool output) is recorded.
3.  **Handle Tool Outputs**: Tool outputs are processed and added to the agent's working memory for the 
agent's working memory for the next cycle.

### 3.3. Observe: State Monitoring and Feedback Collection

This phase is crucial for the agent to understand the impact of its actions and gather information for reflection.

**Key components:**

*   **State Monitor**: Continuously tracks the internal state of the agent (e.g., current goal, active sub-goal, progress, tool outputs, errors) and the external environment (e.g., file system changes, browser state, API responses).
*   **Feedback Collector**: Gathers structured feedback from tool executions, system events, and potentially user interactions. This includes success/failure indicators, error messages, and relevant data generated by tools.
*   **Contextualizer**: Integrates new observations into the agent's current working context, making them available for the Reflection phase.

**Process:**
1.  **Monitor Execution**: Observe the outcome of the executed action (success, failure, partial result).
2.  **Capture Environment State**: Capture relevant changes in the environment (e.g., new files created, web page content updated).
3.  **Update Working Memory**: Store observations and feedback in a temporary working memory accessible to the Reflection component.

### 3.4. Reflect: Learning, Self-Correction, and Adaptation

This is the core of autonomy, where the agent analyzes its performance and adjusts its future behavior.

**Key components:**

*   **Reflection Engine**: An LLM-powered component that analyzes the observations, compares them against the expected outcomes, and identifies discrepancies or failures. It asks questions like: "Did the action achieve the desired outcome?" "Why did it fail?" "What could be done differently?"
*   **Self-Correction Mechanism**: Based on the Reflection Engine's analysis, this mechanism generates corrective actions. This could involve:
    *   **Retrying with modified parameters**: If a tool failed due to incorrect input.
    *   **Generating a new plan**: If the current plan is no longer viable.
    *   **Requesting clarification**: If the problem is ambiguous.
    *   **Updating internal knowledge**: If a new pattern or constraint is discovered.
*   **Long-Term Learning Integration**: Successful strategies and identified failure patterns are distilled and stored in the Semantic Memory for future reference, improving the Dynamic Planner over time.

**Process:**
1.  **Analyze Observations**: The Reflection Engine evaluates the collected feedback and observations against the current sub-goal and plan.
2.  **Identify Discrepancies/Failures**: Determine if the actual outcome matches the expected outcome. If not, identify the root cause of the discrepancy.
3.  **Generate Corrective Actions**: Based on the analysis, the Reflection Engine proposes modifications to the plan, new actions, or updates to the agent's internal state.
4.  **Update Plan/Goal**: The Dynamic Planner incorporates the corrective actions, potentially re-prioritizing sub-goals or generating an entirely new plan.

## 4. Overall Autonomous Loop Flow

The entire process will be an iterative loop:

1.  **Initialize**: Agent receives a user request, Goal Manager sets initial goals.
2.  **Loop Start**:
    a.  **Think**: Dynamic Planner generates a plan for the current sub-goal, leveraging Contextual Reasoning and Semantic Memory.
    b.  **Act**: Execute the first action in the plan using the Enhanced Tool Execution.
    c.  **Observe**: State Monitor and Feedback Collector gather results and environmental changes.
    d.  **Reflect**: Reflection Engine analyzes observations, identifies success/failure, and the Self-Correction Mechanism proposes adjustments.
    e.  **Loop Continue**: If the sub-goal is not yet achieved or if reflection suggests further actions, return to **Think** with an updated context and plan. If the sub-goal is achieved, move to the next sub-goal or report completion.
3.  **Loop End**: All sub-goals are achieved, and the agent reports the final result to the user.

## 5. Architectural Changes and Module Interactions

To support this TAOR loop, several existing modules will be modified, and new components will be introduced:

*   **`agent.js`**: Will be refactored to orchestrate the TAOR loop, managing the flow between phases and integrating with new components.
*   **`planner.js`**: Will evolve into the Dynamic Planner, capable of generating multi-step, iterative plans and incorporating feedback from the Reflection Engine.
*   **`tool-registry.js`**: Will be extended to include tools for internal monologue, state inspection, and dynamic goal management.
*   **`semantic-memory.js`**: Will be actively queried during the Think phase for relevant past experiences and updated during the Reflect phase with new learnings.
*   **`deep-research-agent.js`**: Will be a specialized tool invoked by the Dynamic Planner when complex information gathering is required.
*   **`visual-browser-operator.js`**: Will provide rich observational data for the Observe phase and enable more intelligent web interactions during the Act phase.
*   **`multi-provider-fallback.js`**: Will ensure the reliability of all LLM calls across all phases.
*   **New Module: `goal-manager.js`**: Handles goal decomposition and management.
*   **New Module: `reflection-engine.js`**: Encapsulates the LLM-driven reflection and self-correction logic.
*   **New Module: `context-manager.js`**: Dynamically builds and prioritizes context for the LLM based on the current phase and task.
